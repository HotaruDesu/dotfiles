# 搜索动效与性能验收

2026-11-08：本机三轮逐条配对比较通过约定的延迟门槛。较长的整批压力测试没有全部通过，详见下方限制。两组原始数据均保留在 [motion-benchmark.json](motion-benchmark.json)。

## 三轮配对结果

单位 ms。每项中位数和 P95 的增量均须不超过 `max(5ms, 基线 × 5%)`，下表各项均通过。

| 场景 | 旧版中位数 | 新版中位数 | 旧版 P95 | 新版 P95 |
| --- | ---: | ---: | ---: | ---: |
| 文件搜索：首条实际显示 | 32.94 | 32.28 | 47.00 | 44.42 |
| 文件搜索：整段查询更新 | 57.43 | 34.97 | 382.64 | 243.02 |
| 文件搜索：逐字输入末键到结果 | 46.36 | 34.66 | 321.45 | 270.39 |
| 内容搜索：首条实际显示 | 51.54 | 48.27 | 89.33 | 77.15 |
| 内容搜索：整段查询更新 | 164.62 | 155.94 | 278.27 | 218.46 |
| 内容搜索：逐字输入末键到结果 | 243.78 | 197.29 | 402.57 | 326.99 |
| 选择键映射执行到列表更新 | 0.50 | 0.66 | 22.32 | 20.24 |

每 20ms 切换一次、持续一秒，共 30 组：旧版在松手前均未更新；新版每组更新 **25–32 次**。松手后最终预览内容的 P95 为 **20.89ms**，最大 **21.58ms**，低于 120ms。检查同时比较文件标题和首行内容，另有独立文件内容一致性测试。

## 测量方法

- macOS arm64，Neovim 0.12.5、Neovide 0.16.2、fd 10.4.2、ripgrep 15.1.0。Snacks 提交与配置 SHA-256 记录在 JSON 中。
- 项目固定为 `~/.local/share/nvim/lazy`。两版使用相同 fd/rg 后端、查询、排序和 160×50 布局。OS 文件缓存未清空，不属于磁盘冷启动测试。
- 两个持久 Neovim 测试进程逐条交替 A/B 顺序，每种场景先做相同的 10 次预热。三轮每轮记录 30 次首次显示、30 次整段查询更新、10 次逐字输入、10 次持续选择。每版各有 90/90/30 个查询样本，以及 1500 个选择键样本。
- 逐字输入间隔 20ms，以最后一个字符到对应结果完成计时；不同查询之间会执行对照版本。首次显示须等到列表真正写入非空文字。
- 指示条的 Neovim 开销已计入。选择延迟测的是实际 `<C-j>` 映射回调到列表更新，不包含操作系统键盘传输与屏幕扫描；未测量 GPU 帧率。

## 整批压力测试的限制

此前按完整旧版／新版批次交替、查询紧接查询的压力测试没有全部达标。相同代码的内容搜索首次显示中位数 **45.93 → 55.22ms**、P95 **85.91 → 107.84ms**；查询更新中位数 **144.08 → 153.01ms**；逐字输入 P95 **203.00 → 234.41ms**，均超过对应预算。旧版自身各批次的首次显示中位数也从约 33ms 波动到 72ms。

逐条配对缩短了两版测量间的时间差，同时也改变了不同查询之间的间隔。因此，配对通过证明本机该协议下没有测得超预算退化，不能解释成所有持续压力、后台负载和大型项目均有保证。保留整批脚本和未通过的数据，供后续复现。

## 功能与界面验证

- 异步读取最多一个进行中请求、一个最新待处理请求。覆盖过期结果、关闭后的文件句柄释放、读取期间源缓冲区被修改、未保存内容、中等／超大文件、含控制字符的源码。
- 连续选择时不启动新高亮，稳定后补齐；同文件不同位置复用内容，源缓冲区 Treesitter 保持不变。
- 指示条复用窗口且不抢焦点。覆盖正反向、多选、空结果、布局更新、隐藏／恢复预览及反复关闭。终端与减少动态效果模式不显示指示条。
- 真实 Neovide 中检查了连续 Ctrl+j/k、反向选择、预览翻页、正文移动与滚轮、宽窄布局切换。窗口尺寸已恢复，关闭搜索后无残留浮窗。动画由 Neovide 插值，没有 Lua 逐帧重绘。
- 14 项 Lua 测试中 12 项通过，格式检查通过。`editing.lua:204`（已有全局 codespell 配置）和 `search_finder.lua:131`（原生回退标题断言）在修改前快照中同样失败，相关逻辑未改动。原生文件监听测试在沙箱外通过。

## 复现

修改前完整配置快照位于 `/private/tmp/lunavim-motion-baseline.Xbqzro`：

```sh
LUNAVIM_BENCH_OUTPUT=/tmp/motion-paired.json \
  nvim --headless -u NONE -i NONE -n -l scripts/benchmark_motion_pair.lua \
  /private/tmp/lunavim-motion-baseline.Xbqzro
```

可在最后追加项目路径；默认查询面向当前插件项目，换项目时须选择两版都有结果的相同查询。整批协议使用 `scripts/benchmark_motion.lua`，通过 `LUNAVIM_BENCH_CONFIG` 分别指定配置目录。

[motion-change.patch](motion-change.patch) 保存全部运行时配置改动。在当前配置的独立副本上反向应用该补丁，可恢复这些文件的基线版本。字体、配色主体、方形粒子、搜索后端和 `gd` 行为保持原配置。
